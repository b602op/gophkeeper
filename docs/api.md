# API GophKeeper

HTTP API сервера GophKeeper. Базовый префикс защищённых маршрутов —
`/api/v1`. Формат данных — JSON (`Content-Type: application/json`).

## Аутентификация

Защищённые маршруты требуют заголовок:

```
Authorization: Bearer <JWT>
```

Токен выдаётся эндпоинтом `POST /api/v1/login` и действует в течение времени,
заданного конфигурацией `token_ttl`. Невалидный или истёкший токен приводит к
ответу `401`.

## Формат ошибок

Все ошибки возвращаются в едином виде:

```json
{ "error": "текст ошибки" }
```

| HTTP | Когда возникает |
| --- | --- |
| `400 Bad Request` | некорректное тело или параметры запроса |
| `401 Unauthorized` | неверные учётные данные или невалидный токен |
| `403 Forbidden` | действие запрещено, хотя ресурс виден пользователю (роли, операции над коллекцией) |
| `404 Not Found` | пользователь или секрет не найден, в том числе чужой секрет по ID |
| `409 Conflict` | логин/секрет уже существует либо конфликт версий |
| `500 Internal Server Error` | внутренняя ошибка сервера |

Секреты адресуются по ID, поэтому факт существования чужой записи скрыт:
обращение к чужому секрету неотличимо от обращения к несуществующему и даёт
`404 Not Found` (а не `403`). Это защищает от перебора идентификаторов. Код
`403` остаётся для случаев, когда ресурс виден пользователю, но действие ему
запрещено: проверки ролей, доступ к глобальным административным эндпоинтам и
операции над коллекцией.

## Модель Secret

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | string (UUID) | идентификатор, присваивает сервер |
| `user_id` | string | владелец записи |
| `type` | string | `credentials`, `text`, `binary`, `card` |
| `name` | string | название (до 255 символов) |
| `metadata` | string | произвольная метаинформация (до 64 КиБ) |
| `data` | string (base64) | зашифрованные на клиенте данные (до 1 МиБ) |
| `version` | number | версия для оптимистичной блокировки |
| `created_at` | string (RFC3339) | время создания |
| `updated_at` | string (RFC3339) | время последнего изменения |
| `deleted_at` | string (RFC3339) \| null | время мягкого удаления |

## GET /health

Проверка живости сервера. Не требует авторизации.

**Ответ `200`:**

```json
{ "status": "ok" }
```

## POST /api/v1/register

Регистрация нового пользователя.

**Запрос:**

```json
{
  "login": "alice",
  "password": "secret123"
}
```

- `login` — 3–64 символа, латиница, цифры, `_`, `.`, `-`.
- `password` — 8–72 байта.

**Ответ `201`:**

```json
{
  "id": "0f1c2b3a-4d5e-6f70-8192-a3b4c5d6e7f8",
  "login": "alice"
}
```

**Ошибки:** `400` (невалидные логин/пароль), `409` (логин занят).

Токен при регистрации не выдаётся: клиент выполняет вход отдельным запросом.

---

## POST /api/v1/login

Аутентификация и выдача JWT.

**Запрос:**

```json
{
  "login": "alice",
  "password": "secret123"
}
```

**Ответ `200`:**

```json
{ "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }
```

**Ошибки:** `400`, `401` (неверный логин или пароль).

---

## GET /api/v1/secrets

Список неудалённых секретов текущего пользователя.

**Запрос:**

```bash
curl -H "Authorization: Bearer <JWT>" http://localhost:8080/api/v1/secrets
```

**Ответ `200`:**

```json
{
  "secrets": [
    {
      "id": "79d6edde-204c-49f4-8558-1f0cdc239ac0",
      "user_id": "0f1c2b3a-4d5e-6f70-8192-a3b4c5d6e7f8",
      "type": "credentials",
      "name": "GitHub",
      "metadata": "work",
      "data": "q1pz...",
      "version": 2,
      "created_at": "2026-10-04T10:20:37Z",
      "updated_at": "2026-10-04T10:25:24Z",
      "deleted_at": null
    }
  ]
}
```

## POST /api/v1/secrets

Создание секрета. Поля `id`, `user_id`, `version`, `created_at`, `updated_at`
игнорируются и проставляются сервером.

**Запрос:**

```json
{
  "type": "credentials",
  "name": "GitHub",
  "metadata": "work",
  "data": "q1pz...",
  "version": 1
}
```

**Ответ `201`:** созданный объект `Secret` с присвоенными полями.

**Ошибки:** `400` (неизвестный тип, пустые или слишком большие данные),
`401`, `409` (секрет с таким id уже существует).

---

## GET /api/v1/secrets/{id}

Получение секрета по идентификатору.

**Ответ `200`:** объект `Secret`.

**Ошибки:** `401`, `404` (секрет не найден, удалён или принадлежит другому
пользователю).

---

## PUT /api/v1/secrets/{id}

Обновление секрета с оптимистичной блокировкой.

**Запрос:** тело как при создании; поле `version` должно совпадать с текущей
версией записи на сервере.

```json
{
  "type": "credentials",
  "name": "GitHub",
  "metadata": "work",
  "data": "bmV3...",
  "version": 2
}
```

**Ответ `200`:** объект `Secret` с увеличенной `version` и обновлённым
`updated_at`.

**Ошибки:** `400`, `401`, `404` (секрет не найден, удалён или принадлежит
другому пользователю), `409` (конфликт версий — `ErrSecretVersionMismatch`;
клиент разрешает его интерактивно).

---

## DELETE /api/v1/secrets/{id}

Мягкое удаление: запись помечается `deleted_at`, но остаётся в базе, чтобы
другие клиенты узнали об удалении при синхронизации.

**Ответ `204`:** без тела.

**Ошибки:** `401`, `404` (секрет не найден, уже удалён или принадлежит другому
пользователю).

## GET /api/v1/sync

Синхронизация изменений.

**Параметры:**

| Параметр | Обязателен | Описание |
| --- | --- | --- |
| `since` | нет | момент в формате RFC3339; возвращаются записи, изменённые строго после него |

Без `since` возвращаются все неудалённые секреты. С `since` возвращаются все
изменённые записи, **включая удалённые** (`deleted_at != null`) — так клиенты
узнают об удалениях.

**Запрос:**

```bash
curl -H "Authorization: Bearer <JWT>" \
  "http://localhost:8080/api/v1/sync?since=2026-01-15T10:30:00Z"
```

**Ответ `200`:**

```json
{
  "secrets": [
    {
      "id": "1cf3284f-3e77-4e7e-8e8b-ff16bfd0f616",
      "type": "card",
      "name": "Sber",
      "version": 3,
      "updated_at": "2026-01-15T10:31:00Z",
      "deleted_at": null
    }
  ]
}
```

**Ошибки:** `400` (некорректный `since`), `401`.

## Пример полного цикла

```bash
# Регистрация
curl -X POST http://localhost:8080/api/v1/register \
  -H "Content-Type: application/json" \
  -d '{"login":"alice","password":"secret123"}'

# Вход
TOKEN=$(curl -s -X POST http://localhost:8080/api/v1/login \
  -H "Content-Type: application/json" \
  -d '{"login":"alice","password":"secret123"}' | jq -r .token)

# Создание секрета
curl -X POST http://localhost:8080/api/v1/secrets \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"type":"text","name":"Note","metadata":"","data":"c2VjcmV0","version":1}'

# Список
curl -H "Authorization: Bearer $TOKEN" http://localhost:8080/api/v1/secrets

# Синхронизация
curl -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8080/api/v1/sync?since=2026-01-15T10:30:00Z"
```
